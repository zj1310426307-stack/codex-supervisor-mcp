# Phase 03 verifier leases

Every verifier run first owns a durable run ID, worker ID, instance ID, lease ID, digest image, exact OCI engine/store namespace, heartbeat, expiry, and before snapshot. The full container ID/hash, recipe, and label hash are added atomically when the worker reports its first owned container. A crash before that event therefore has a valid pre-container run without a container ID. Host-process verification is disabled. Heartbeats and engine-client exit are observations, not proof that a container is dead.

If ownership or termination is uncertain, the run becomes lost/quarantined. Reconciliation is serialized by the task operation lock, targets one exact run ID, and produces PROVEN_TERMINATED, PROVEN_STILL_RUNNING, or UNKNOWN. It verifies the durable engine namespace, old image digest, full container ID, labels, and inspected image; current configuration may use a newer image digest. PROVEN_STILL_RUNNING retains a cleanup-blocking running state and creates an exact task/run quarantine; the same exact quarantined run may be re-observed later after the container exits. Only positive termination proof clears that scoped quarantine. Cross-task run selection is rejected.

Normal completion is subject to the same proof as timeout handling: the exact label-verified container must report stopped with PID zero and be removed. If it is still running, the worker terminates it and marks the recipe non-passing. Docker/Podman unavailability is a hard runtime error and never causes a host fallback.

Startup invalidates every prior-runtime active/terminating verifier lease independently of run state. Active runs become lost and quarantined. A contradictory active lease attached to a terminal run is normalized to terminal only when complete OCI termination evidence already proves every recipe container removed. If the task itself was still `verifying`, its old candidate is marked stale and must be verified again; an already-terminal task keeps its completed evidence. Missing or incomplete terminal evidence becomes lost/quarantined. A task left in `verifying` with no run or lease returns to `awaiting_verification`; an orphan lease without a run remains blocked and quarantined.
